# Introduction

Kiro hooks are a powerful automation system that allows you to trigger AI agent actions based on specific events in your development workflow. Unlike steering files that provide guidance for code generation, hooks enable proactive automation that responds to file changes, user actions, and other development events.

# C# Documentation Scanner Hook

**File**: `.kiro/hooks/six-template-doc-scan-hook.kiro.hook`

This hook automatically scans project documentation when working with C# files to provide relevant context for better task execution.

### Configuration

```json
{
  "enabled": true,
  "name": "C# Documentation Scanner",
  "description": "When working with C# files, automatically scan documentation for relevant knowledge related to the user's prompt or task to provide additional context for better task execution",
  "version": "1",
  "when": {
    "type": "fileEdited",
    "patterns": [
      "**/*.cs"
    ]
  },
  "then": {
    "type": "askAgent",
    "prompt": "A user prompt has been sent regarding a C# file. Before proceeding with the task, scan the available documentation (*.md or *.mdx files) in the #[[file:docs/src/content/docs/]] directory and any other relevant documentation to find knowledge related to the user's prompt or task. If you find relevant documentation, incorporate it as additional context to enhance your understanding and execution of the task. Pay special attention to C# coding standards, patterns, and best practices documented in the project."
  }
}
```

### How It Works

1. **Trigger**: Activates when any `.cs` file is edited
2. **Action**: Asks the AI agent to scan project documentation
3. **Context**: Provides relevant documentation context for C# development tasks
4. **Benefit**: Ensures AI responses incorporate project-specific knowledge and standards

### Use Cases

- Automatically reference coding standards when modifying C# files
- Include relevant architectural patterns in code suggestions
- Ensure consistency with documented best practices
- Provide context-aware suggestions based on project documentation

# In-Repository Documentation Updater Hook

**File**: `.kiro/hooks/six-template-update-docs-hook.kiro.hook`

This hook automatically updates documentation when source code or configuration files are modified to keep documentation synchronized with the codebase.

### Configuration

```json
{
  "enabled": true,
  "name": "In-Repository Documentation Updater",
  "description": "Automatically updates documentation files when source code, configuration files, or other project files are modified to keep documentation in sync with the codebase",
  "version": "1",
  "when": {
    "type": "fileEdited",
    "patterns": [      
      "global.json",
      "nuget.config",
      "AGENTS.md",
      "README.md",
      "GitVersion.yml",
      ".github/workflows/*.yml",
      ".github/workflows/*.yaml",
      "**/*.xaml",
      "**/*.axaml",
      "**/*.sln",
      "**/*.slnx",
      "**/*.csproj",
      "**/*.cs"
    ]
  },
  "then": {
    "type": "askAgent",
    "prompt": "Files have been modified in the repository. Use the steering rules specified for documentation writing in #[[file:.kiro/steering/dotnet/general/dotnet-docs.md]], please review the changes and update any relevant documentation files in #[[file:docs/src/content/docs/]], code comments, etc.) to ensure they accurately reflect the current state of the codebase. Focus on updating documentation that may be affected by the file changes, including installation instructions, usage examples, API references, configuration guides, and any other user-facing documentation."
  }
}
```

### How It Works

1. **Trigger**: Activates when key project files are modified
2. **Action**: Asks the AI agent to review and update relevant documentation
3. **Context**: Uses documentation steering files for consistent updates
4. **Benefit**: Keeps documentation synchronized with code changes automatically

### Use Cases

- Update API documentation when code interfaces change
- Refresh configuration guides when settings files are modified
- Update installation instructions when project structure changes
- Maintain accurate code examples in documentation

# Troubleshooting

## Common Issues

### Hook Not Triggering
- Check file patterns match the modified files
- Verify the hook is enabled
- Ensure proper JSON syntax in configuration

### Unexpected Triggers
- Review file patterns for overly broad matching
- Add exclusion patterns using `!pattern` syntax
- Check for hidden files or directories being matched

### Poor AI Responses
- Refine prompts to be more specific
- Add relevant context and steering file references
- Break complex tasks into smaller, focused hooks
