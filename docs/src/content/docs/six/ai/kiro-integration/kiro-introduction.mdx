# Overview

The **Six.SolutionTemplate** includes a comprehensive set of **Kiro steering files** organized in the `.kiro/steering/` directory.
These steering files provide detailed guidance for AI-assisted development, ensuring consistent code quality, proper architectural
patterns, and streamlined development workflows across different technologies and development scenarios.

Kiro steering files are configuration files (`.md` format) that help AI coding assistants understand your project's specific requirements,
coding standards, and best practices. They act as a bridge between your development team's knowledge and AI tools,
ensuring consistent and high-quality code generation.

## Hierarchical Organization

The steering files are organized hierarchically by technology and purpose, making it easy to find and apply the 
right guidance for your development context:

```
.kiro/steering/
├── dotnet/                   # .NET development steering files
│   ├── aspnet/               # ASP.NET Core API development
│   ├── avalonia/             # Avalonia desktop applications
│   ├── blazor/               # Blazor web applications
│   ├── ci-cd/                # CI/CD workflows and automation
│   ├── csharp/               # C# language and coding standards
│   └── general/              # General .NET patterns and practices
├── web/                      # Web development steering files
│   ├── astro/                # Astro.js framework development
│   └── typescript/           # TypeScript development standards
└── documentation/            # Documentation best practices
    ├── agents-md.md          # AI agent documentation standards
    ├── readme-md.md          # README file best practices
    └── tech-writer.md        # Steering for technical writing
```


## How Steering Files Work

### Automatic Application
Steering files are automatically applied by Kiro based on:
- **File patterns**: Steering files target specific file types using glob patterns (e.g., `**/*.cs`, `**/*.ts`, `**/*.mdx`)
- **Directory context**: Steering files apply when working in relevant project directories
- **Project structure**: Steering files activate based on detected frameworks and project configuration
- **Always-apply settings**: Some steering files can be configured to always apply regardless of context

### Manual Reference
You can explicitly reference steering files in your prompts using the hierarchical path structure:
```
#[[file:.kiro/steering/dotnet/csharp/csharp-coding-style.md]] Create a user service
#[[file:.kiro/steering/web/typescript/typescript-coding-style.md]] Implement validation
```

### Steering File Combinations
Multiple steering files can work together:
```
#[[file:.kiro/steering/dotnet/aspnet/aspnet-api.md]] #[[file:.kiro/steering/dotnet/general/dotnet-testing.md]] Create an API with tests
```

### Steering File Format
All steering files use the `.md` (Markdown) format, which includes:
- **Frontmatter metadata**: Description, file patterns, and application settings
- **Structured content**: Role definitions, requirements, and detailed guidance
- **Practical examples**: Code samples showing both recommended and discouraged patterns
- **Integration guidance**: How steering files work together and complement each other

## Kiro Hooks System

In addition to steering files, Kiro includes a powerful **hooks system** that enables automated workflow triggers:

- **Event-Driven Automation**: Hooks respond to file changes, user actions, and other development events
- **AI Agent Integration**: Hooks can automatically trigger AI agent actions with specific prompts
- **Workflow Enhancement**: Automate documentation updates, code analysis, and development workflows
- **Context-Aware Actions**: Hooks provide relevant context to AI agents for better task execution

Learn more about the [Kiro Hooks System](https://kiro.dev/docs/hooks/).
