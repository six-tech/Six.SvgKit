# Introduction

The Documentation Rules provide comprehensive guidance for creating professional, maintainable documentation that serves both human readers and AI systems. These rules ensure consistent, high-quality documentation across all project types with emphasis on clarity, accessibility, and technical accuracy.

<Aside type="note">
**Rule Interdependencies**: Many rules reference and build upon other rules to ensure consistent code generation. 
    
    For example, ASP.NET Core rules automatically incorporate C# coding style guidelines, so all generated API code follows the same performance patterns, memory management, and modern language features. 
    
    This creates a cohesive development experience where all code maintains consistent quality and style across different technologies.
</Aside>

# README.md Documentation Rules

The **README.md Documentation Rules** establish standards for creating comprehensive, professional README files that 
provide clear project information, setup instructions, and usage guidance for both developers and users.

### What It Does

This rule provides guidance for:
- Creating clear, comprehensive project overviews and descriptions
- Writing detailed setup and installation instructions
- Documenting usage examples and API references
- Maintaining consistent formatting and structure across projects
- Including proper metadata and badges for project visibility

### File Patterns
- `README.md` files in project roots
- Project documentation and setup files
- Documentation configuration files

# Technical Writing Rules

The **Technical Writing Rules** establish professional guidelines for creating clear, consistent, and accessible 
technical documentation that serves both human readers and automated systems effectively.

### What It Does

This rule provides comprehensive guidance for:

- **Language and Style**: Using clear, concise language appropriate for the target audience
- **Content Structure**: Organizing content with logical flow and proper heading hierarchy
- **Code Examples**: Including relevant code samples and detailed explanations
- **Step-by-Step Instructions**: Providing clear, actionable guidance when needed
- **Consistent Terminology**: Maintaining uniform terms and formatting throughout documentation
- **Troubleshooting**: Including common pitfalls and their solutions
- **Accessibility**: Ensuring documentation is scannable and well-organized for quick reference

### File Patterns
- General technical documentation files
- API guides and tutorials
- Implementation guides and user manuals
- Technical specification documents
- Documentation directories and content files
