# Introduction

The .NET rules provide comprehensive guidance for modern .NET development across all platforms and application types, from web APIs to desktop applications, with emphasis on performance, maintainability, and industry best practices.

<Aside type="note">
**Rule Interdependencies**: Many rules reference and build upon other rules to ensure consistent code generation. 
    
    For example, ASP.NET Core rules automatically incorporate C# coding style guidelines, so all generated API code follows the same performance patterns, memory management, and modern language features. 
    
    This creates a cohesive development experience where all code maintains consistent quality and style across different technologies.
</Aside>

# General .NET Development

<a id="solution-structure-rules"></a>
## Solution Structure Rules

The Solution Structure Rules provide guidance for organizing .NET solutions with consistent build configuration, SDK management, and project structure. These rules ensure maintainable, scalable solution architectures across teams and projects.

### What It Does

This rule enforces proper .NET solution organization by:
- Standardizing solution-wide build properties through `Directory.Build.props`
- Managing SDK versions consistently with `global.json`
- Establishing consistent project structure and naming conventions
- Configuring EditorConfig for code style enforcement across the solution

### File Patterns
- `*.sln` and `*.slnx` solution files
- `Directory.Build.props` and `Directory.Build.targets`
- `global.json` and `nuget.config`
- Project organization in logical folder structures

<a id="testing-rules"></a>
## Testing Rules

The Testing Rules establish comprehensive testing strategies using xUnit framework with patterns for unit testing, integration testing, test data management, and continuous testing practices.

### What It Does

This rule provides guidance for:
- Implementing effective unit and integration testing strategies
- Using xUnit framework with parallel execution and test categories
- Establishing mocking strategies and test data management
- Configuring test environments and CI/CD integration

### File Patterns
- `*.Test.*.csproj` test project files
- `tests/**/*.cs` test source files
- Test configuration and setup files

# C# Coding Style

<a id="csharp-coding-style-rules"></a>
## C# Coding Style Rules

The C# Coding Style Rules establish modern C# coding standards leveraging the latest language features, performance patterns, and maintainable code practices for building robust applications.

### What It Does

This rule enforces:
- Modern C# language features (C# 13) including collection expressions and primary constructors
- Performance-oriented patterns with Span&lt;T&gt;, Memory&lt;T&gt;, and ValueTask
- Memory management best practices with ArrayPool and stackalloc
- Code quality standards with analyzers and nullable reference types

### File Patterns
- All `*.cs` files in .NET projects
- `*.csproj` project configuration files
- `.editorconfig` and analyzer configuration files
