# Overview

The **Six.SolutionTemplate** includes a comprehensive set of **Cursor rules** organized in the `.cursor/rules/` directory.
These rules provide detailed guidance for AI-assisted development, ensuring consistent code quality, proper architectural
patterns, and streamlined development workflows across different technologies and development scenarios.

Cursor rules are configuration files (`.mdc` format) that help AI coding assistants understand your project's specific requirements,
coding standards, and best practices. They act as a bridge between your development team's knowledge and AI tools,
ensuring consistent and high-quality code generation.

## Hierarchical Organization

The rules are organized hierarchically by technology and purpose, making it easy to find and apply the right guidance for your development context:

```
.cursor/rules/
├── dotnet/                   # .NET development rules
│   ├── aspnet/               # ASP.NET Core API development
│   ├── avalonia/             # Avalonia desktop applications
│   ├── blazor/               # Blazor web applications
│   ├── ci-cd/                # CI/CD workflows and automation
│   ├── csharp/               # C# language and coding standards
│   └── general/              # General .NET patterns and practices
├── web/                      # Web development rules
│   ├── astro/                # Astro.js framework development
│   └── typescript/           # TypeScript development standards
├── documentation/            # Documentation best practices
│   ├── agents-md.mdc         # AI agent documentation standards
│   ├── readme-md.md          # README file best practices
│   └── tech-writer.md        # Steering for technical writing
└── specs-generation/         # Specification-driven development
    └── coding-by-spec.mdc    # Spec-driven development patterns
```


## How Rules Work

### Automatic Application
Rules are automatically applied by Cursor based on:
- **File patterns**: Rules target specific file types using glob patterns (e.g., `**/*.cs`, `**/*.ts`, `**/*.mdx`)
- **Directory context**: Rules apply when working in relevant project directories
- **Project structure**: Rules activate based on detected frameworks and project configuration
- **Always-apply settings**: Some rules can be configured to always apply regardless of context

### Manual Reference
You can explicitly reference rules in your prompts using the hierarchical path structure:
```
@.cursor/rules/dotnet/csharp/csharp-coding-style.mdc Create a user service
@.cursor/rules/web/typescript/typescript-coding-style.mdc Implement validation
```

### Rule Combinations
Multiple rules can work together:
```
@.cursor/rules/dotnet/aspnet/aspnet-api.mdc @.cursor/rules/dotnet/general/dotnet-testing.mdc Create an API with tests
```

### Rule File Format
All rules use the `.mdc` (Markdown with Cursor) format, which includes:
- **Frontmatter metadata**: Description, file patterns, and application settings
- **Structured content**: Role definitions, requirements, and detailed guidance
- **Practical examples**: Code samples showing both recommended and discouraged patterns
- **Integration guidance**: How rules work together and complement each other
