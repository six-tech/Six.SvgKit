# Introduction

The **Six Solution Template** includes comprehensive AI documentation rules designed to work seamlessly with popular
AI coding assistants like **Cursor** and **Amazon's Kiro**.

These rules provide standardized guidelines and best practices for generating high-quality documentation across different types of content.

<Aside type="tip">
    **How to Use**: Reference these rules in your AI assistant by using the appropriate syntax:
    - **Cursor**: `rule-name.mdc` (e.g., `readme-md.mdc`)
    - **Kiro**: `rule-name.md` (e.g., `readme-md.md`)
</Aside>


# Available Documentation Rules

The template provides specialized rules for different types of documentation, ensuring consistent quality and professional standards across all content types.


## README.md Generation

This rule provides comprehensive guidelines for creating professional README files that effectively communicate your project's value and usage.

**Available Formats:**
- **Cursor**: `readme-md.mdc`
- **Kiro**: `readme-md.md`

**What it instructs the AI to do:**
- Structure README with clear sections (Overview, Features, Installation, Usage, etc.)
- Include essential project information (badges, screenshots, demo links)
- Write compelling descriptions that highlight key benefits
- Provide clear installation and setup instructions
- Include code examples and API documentation links
- Add contribution guidelines and license information
- Ensure consistent formatting and professional presentation


----

## AGENTS.md Generation

This rule focuses on creating comprehensive documentation specifically for AI coding agents,
ensuring they have all the context and instructions needed to work effectively with your codebase.

**Available Formats:**
- **Cursor**: `agents-md.mdc`
- **Kiro**: `agents-md.md`

**What it instructs the AI to do:**
- Document project structure and conventions
- Explain coding standards and style guidelines
- Provide context about technology stack and frameworks
- Include setup and development workflow instructions
- Document API patterns and architectural decisions
- Explain testing and deployment processes
- Include troubleshooting guides and common issues



----


## Technical Writing Standards

This rule establishes professional standards for all technical documentation, ensuring clarity, consistency, and readability across all content types.

**Available Formats:**
- **Cursor**: `tech-writer.mdc`
- **Kiro**: `tech-writer.md`

**What it instructs the AI to do:**
- Use the clear, concise language appropriate for the audience
- Structure content with logical flow and proper headings
- Include relevant code examples and explanations
- Provide step-by-step instructions when needed
- Use consistent terminology and formatting
- Include troubleshooting information and common pitfalls
- Ensure documentation is scannable and well-organized



----


## .NET Documentation Rules

This specialized rule provides guidelines specifically for documenting .NET projects, including C# code, APIs, and .NET-specific concepts.

**Available Formats:**
- **Cursor**: `dotnet-docs.mdc`
- **Kiro**: `dotnet-docs.md`

**What it instructs the AI to do:**
- Document .NET concepts (async/await, LINQ, dependency injection, etc.)
- Explain C# language features and best practices
- Provide clear API documentation with examples
- Include XML documentation comments standards
- Document NuGet package usage and configuration
- Include performance considerations and best practices
