# Introduction

The template uses a centralized `Nuget.config` file that defines four distinct package sources:

1. **Local Feed** - For local testing and development (could also be used as a development feed I team shares a
common directory; for example, on One Drive or similar)
2. **Development Feed** - For development packages
3. **Staging Feed** - For staging packages
4. **Production Feed** - For production releases (for example, if the package is free, on NuGet.org)

<Aside type="tip">
    All configuration values (feed urls, usernames and secrets [personal access tokens]) **are stored as environment
    variables**, ensuring security and flexibility across different development environments.

    See more how to configure them in the [NuGet Secrets](./nuget-secrets/) documentation.
</Aside>




# Feed Configuration

The `Nuget.config` file is located in the solution root and contains:

```xml
<configuration>
    <packageSources>
        <clear />
        <add key="Local" value="%NUGET_FEED_LOCAL_URL%" />
        <add key="Development" value="%NUGET_FEED_DEV_URL%" />
        <add key="Staging" value="%NUGET_FEED_STAGING_URL%" />
        <add key="Production" value="%NUGET_FEED_PRODUCTION_URL%" />
    </packageSources>
    
    <packageSourceCredentials>
        <Development>
            <add key="Username" value="%NUGET_FEED_DEV_USERNAME%" />
            <add key="ClearTextPassword" value="%NUGET_FEED_DEV_PAT%" />
        </Development>
        <Staging>
            <add key="Username" value="%NUGET_FEED_STAGING_USERNAME%" />
            <add key="ClearTextPassword" value="%NUGET_FEED_STAGING_PAT%" />
        </Staging>
        <Production>
            <add key="Username" value="%NUGET_FEED_PRODUCTION_USERNAME%" />
            <add key="ClearTextPassword" value="%NUGET_FEED_PRODUCTION_PAT%" />
        </Production>
    </packageSourceCredentials>
</configuration>
```


# Troubleshooting

----

## Common Issues

### 1. Environment Variables Not Found

**Symptoms**: The build script fails with "environment variable is required" errors

**Solution**: Verify environment variables are set and accessible in your terminal session

```bash
# Check if variables are set
echo $NUGET_FEED_LOCAL_URL
echo $NUGET_FEED_PRIVATE_URL
```

### 2. Authentication Failures

**Symptoms**: Package push fails with 401 Unauthorized errors

**Solution**: Verify PAT is valid and has correct permissions

### 3. Feed URL Issues

**Symptoms**: Package push fails with feed not found errors

**Solution**: Verify feed URL is correct and accessible from your network

## Debug Mode

Use the `--debug` flag to get more detailed output:

```bash
dotnet run build/nuget-pack.cs --debug --local
```


# Advanced Configuration

----

<Aside type="tip">
    **Important**: If you change environment variable names in `Nuget.config`, you must also update the corresponding
    variables in `build/nuget-pack.cs` to maintain compatibility.
</Aside>

## Custom Feed Names

You can modify the feed keys in `Nuget.config` to match your organization's naming conventions:

```xml
<add key="CompanyInternal" value="%NUGET_FEED_PRIVATE_URL%" />
<add key="CompanyStaging" value="%NUGET_FEED_STAGING_URL%" />
```

## Multiple Private Feeds

For organizations with multiple private feeds, you can extend the configuration:

```xml
<add key="Internal" value="%NUGET_FEED_INTERNAL_URL%" />
<add key="Staging" value="%NUGET_FEED_STAGING_URL%" />
<add key="Production" value="%NUGET_FEED_PRODUCTION_URL%" />
```

Remember to add corresponding credentials and update the build script accordingly.
