# Overview

The `Six.SolutionTemplate` uses environment variables to securely manage NuGet feed credentials, ensuring that 
sensitive information like **Personal Access Tokens (PATs) and usernames are never committed to source control.**

This approach provides maximum security and flexibility across different development environments while maintaining ease of use.

## Why Environment Variables?

Environment variables offer several critical advantages for credential management:

- **Security**: Credentials are stored outside source code, preventing accidental exposure in version control
- **Flexibility**: Different environments (development, staging, production) can use different credentials without code changes
- **Team Collaboration**: Each developer can configure their own credentials without affecting others
- **CI/CD Integration**: Build systems can securely inject credentials during automated processes

## Credential Types

The template supports four distinct feed types, each with its own set of credentials:

1. **Local Feed** - No credentials required, uses the local directory path only
2. **Development Feed** - Requires URL, username, and PAT for team collaboration
3. **Staging Feed** - Requires URL, username, and PAT for pre-production testing
4. **Production Feed** - Requires URL, username, and PAT for final releases (e.g., NuGet.org)


# Environment Variables

<Aside type="tip">
    Configure only the variables needed for your intended distribution strategy
</Aside>

## Required Variables

| Variable | Purpose |
|:---------|:--------|
| `NUGET_FEED_LOCAL_URL` | Local directory path for development packages |
| `NUGET_FEED_DEV_URL` | Development NuGet feed URL |
| `NUGET_FEED_DEV_USERNAME` | Username for development feed |
| `NUGET_FEED_DEV_PAT` | Personal Access Token for development feed |
| `NUGET_FEED_STAGING_URL` | Staging NuGet feed URL |
| `NUGET_FEED_STAGING_USERNAME` | Username for staging feed |
| `NUGET_FEED_STAGING_PAT` | Personal Access Token for staging feed |
| `NUGET_FEED_PRODUCTION_URL` | Production NuGet feed URL |
| `NUGET_FEED_PRODUCTION_USERNAME` | Username for production feed |
| `NUGET_FEED_PRODUCTION_PAT` | Personal Access Token for production feed |

<Aside type="tip">
    **Important**: If you change environment variable names in `Nuget.config`, you must also update the corresponding
    variables in `build/nuget-pack.cs` to maintain compatibility.
    
    See more in the [NuGet Feeds](./nuget-feeds/) and [NuGet Publishing](./nuget-publish/) documentation.
</Aside>

<Aside type="tip">
    **Important**: If you don't need certain feeds (e.g., Local or Staging) and you didn't set environment
    variables for them, **you should remove them from `Nuget.config`** in the solution root or compiler will error if 
    environment variables for them are missing/not set.
</Aside>


## Environment Variable Setup

<Tabs>
    <TabItem label="Windows (Windows Settings)">
        Use Windows Environment Variables:

        1. Open System Properties → Advanced → Environment Variables
        2. Add each variable under User Variables
        3. Restart your terminal/IDE after adding variables
    </TabItem>

    <TabItem label="Windows (PowerShell)">
        ```powershell
        # Local development
        $env:NUGET_FEED_LOCAL_URL = "C:\LocalNuGetFeed"

        # Development feed
        $env:NUGET_FEED_DEV_URL = "https://nuget.pkg.github.com/NAMESPACE/index.json"
        $env:NUGET_FEED_DEV_USERNAME = "your-nuget-feed-username"
        $env:NUGET_FEED_DEV_PAT = "your-dev-pat-token"

        # Staging feed
        $env:NUGET_FEED_STAGING_URL = "https://nuget.pkg.github.com/NAMESPACE/index.json"
        $env:NUGET_FEED_STAGING_USERNAME = "your-nuget-feed-username"
        $env:NUGET_FEED_STAGING_PAT = "your-staging-pat-token"

        # Production feed
        $env:NUGET_FEED_PRODUCTION_URL = "https://api.nuget.org/v3/index.json"
        $env:NUGET_FEED_PRODUCTION_USERNAME = "your-nuget-feed-username"
        $env:NUGET_FEED_PRODUCTION_PAT = "your-production-pat-token"
        ```
    </TabItem>

    <TabItem label="Windows (Command Prompt)">
