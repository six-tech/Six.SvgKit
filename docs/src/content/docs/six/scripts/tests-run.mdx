# Overview

The **Test Runner** (`tests-run.cs`) provides test execution capabilities for all test projects in the **Six 
Solution Template** solution. 
It automatically discovers test projects, runs them with detailed output, and provides reporting on test results.

# Purpose

The test runner automates test execution by:
- **Automatic Discovery**: Finds all test projects in the solution
- **Detailed Reporting**: Shows individual test results with pass/fail/skip status
- **Comprehensive Analysis**: Provides summary statistics and timing information
- **Error Handling**: Graceful handling of test failures and execution errors
- **Cross-Platform**: Works consistently across Windows, macOS, and Linux

# Usage

```bash
dotnet run scripts/tests-run.cs
```

## What It Does

1. **Project Discovery**: Scans for test projects in the `tests/` directory
2. **Filtering**: Excludes non-test projects and build artifacts
3. **Sequential Execution**: Runs each test project individually
4. **Result Parsing**: Extracts detailed test results from output
5. **Summary Reporting**: Displays comprehensive test statistics

# Test Project Discovery

## Automatic Detection

The script automatically finds test projects by:
- Scanning the `tests/` directory recursively
- Looking for `*.Tests*.csproj` files
- Excluding `bin/` and `obj/` directories
- Filtering out non-test projects


# Configuration

## Test Execution Parameters

The script uses the following parameters for test execution:
- `--logger "console;verbosity=normal"`: Detailed console output
- `--no-restore`: Skips package restoration (assumes already restored)
- Standard dotnet test parameters for consistency

## Project Filtering

You can modify the ignored projects list by editing the script:

```csharp
var ignoredProjects = new List<string>
{
    "Six.KeycloakAdmin.Tests.AppHost", // Aspire app host
    "YourProject.Tests.Integration"    // Add your own exclusions
};
```
